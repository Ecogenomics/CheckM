Performance

The run time, memory and disk space used by lineage_wf were measured for CheckM 1.2.7, 1.2.10 and 1.3.0 on two sets of genomes randomly selected from the non-isolate (metagenome-assembled and single-cell) genomes in GlobDB release 232:

  • 128 genomes (112 bacteria and 16 archaea)

  • 1,000 genomes (875 bacteria and 125 archaea)

CheckM 1.3.0 places genomes in the reference genome tree with gPlace instead of pplacer. CheckM 1.3.0 and 1.2.10 gave identical marker lineages, completeness, contamination and strain heterogeneity for all genomes. CheckM 1.2.7 differed for 1 of the 128 genomes and 6 of the 1,000 genomes due to bug fixes in CheckM 1.2.8 (see Change log).

  • Peak memory is the peak memory of the whole workflow.

  • Placement memory is the peak memory of the step that places genomes in the reference genome tree (pplacer for CheckM <= 1.2.10, gPlace for CheckM 1.3.0). This step sets the peak memory of the workflow, except when gPlace’s memory is limited with --gplace_max_memory: the peak (8.4 GiB) is then reached while calling genes with 64 threads at the start of the workflow.

  • Output size is the size of the output folder. Most output files are gzip-compressed from CheckM 1.3.0 (see Output files).

Placing genomes in the tree took 3.7 min (128 genomes) and 5.5 min (1,000 genomes) with pplacer, and 14 s and 19 s with gPlace. Limiting gPlace to 8 GiB of memory increased this to 53 s for 1,000 genomes, as gPlace then places genomes tile by tile, and gave identical results.

With 1,000 genomes, CheckM 1.3.0 takes 19% less time than CheckM 1.2.10 and needs 61% less memory and 72% less disk space. The memory used by gPlace depends little on the number of genomes, as most of it holds the reference genome tree. The memory used while calling genes and placing genomes increases with the number of threads.

Methods

  • Machine: 2x AMD EPYC 7402 24-core processors (96 threads) and 502 GB of memory, running Linux.

  • Commands: checkm lineage_wf -t 64 -x fna <genome folder> <output folder>, with --pplacer_threads 64 for CheckM <= 1.2.10. Runs were made one at a time.

  • Software: HMMER 3.4, Prodigal 2.6.3, pplacer 1.1.alpha20 (CheckM <= 1.2.10) and gPlace 0.1.0 (CheckM 1.3.0).

  • Memory: the memory of all processes started by CheckM was sampled once a second from the memory cgroup of the run. This counts memory shared between processes once, which matters as pplacer and gPlace use worker processes that share the reference genome tree; the largest single process (as reported by /usr/bin/time -v) used 34.9 GiB with pplacer and 12.0 GiB with gPlace. Memory used by the kernel to cache files is not included. The memory in use on the whole machine agreed to within 0.2 GiB.
